## GitHub 优先：先调研，再选择，再实施

- 当我要求新建工具、应用、自动化、插件或新增较大功能时，先使用已安装的 github-first 技能，深入搜索 GitHub 的现成应用、项目和可复用组件，再决定实现方案。小修小改、解释代码和正常使用已有工具不触发。
- 即使技能未自动选用，也要执行本段核心流程。技能不可用时如实说明，使用可用的 GitHub 或网页搜索工具继续调研，不假装已加载技能。
- 必要时查看源码、Releases 和关键 Issues，核实功能、平台、部署难度、费用、维护情况与许可证。不要只按 Star 数推荐，不编造搜索或测试结果。
- 综合权衡并给出来源链接、推荐理由、关键不足和不确定性，通常展示 3–5 个值得考虑的候选，不凑数量。当前任务的明确要求优先。
- 默认等我选定后再安装或开发；选择前只做必要的调研与只读检查。若我已选定或明确授权本次自主决定，不重复询问。
- 未找到合适方案时说明搜索范围和不适配原因，再提供自行开发或组合组件的选项。网络失败不等于没有现成方案，由我决定是否跳过调研。
- 复用同一任务已完成的调研。我当次明确要求跳过、从零学习或直接采用指定项目时，遵循当次要求。
